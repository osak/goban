# 設計: SGF をコアにした内部表現と変化図

状態: 方針決定済み（§12）。§13 の仕様確認は済み。段階 1（SGF のコア）・段階 2（アプリの載せ替え）・段階 3（変化図の UI）・段階 4（ツリーの表示・「配置」モード・コメント）を実装済み。

## 1. 目的と方針

- 盤面の内部表現を、SGF のゲームツリーと同等のデータ構造にする。保存・読み込み・書き出しはすべてこの表現を通す。
- 変化図（分岐した手順）を扱えるようにする。
- 方針:
  1. **SGF で表せるものは SGF の標準のプロパティで表す。**
  2. **SGF で表せないものだけを独自プロパティ（拡張）で足す。** 拡張は SGF の構文には従うので、ほかのソフトで開いても壊れず、無視されるだけにする。
  3. **SGF の外に置くのは、記録ではなく画面や入力の状態だけにする**（表示範囲・選んでいる道具・今いるノードなど）。
  4. 読み込んだ SGF の知らないプロパティは捨てずに持ち、そのまま書き出す（往復で情報を落とさない）。
- 盤の配列（`Board`）は残す。ただし「記録」ではなく、ツリーから導出するキャッシュという位置づけにする。描画・当たり判定・取りの判定は今のコードを使う。

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| ノード | SGF のノード（`;` で始まるプロパティの集まり） |
| 着手ノード | `B` / `W` を持つノード。拡張の「取りなしの着手」（§4.2 `GBMV`）も着手として扱う |
| 配置ノード | 着手を持たず、`AB` / `AW` / `AE` / `PL` を持ちうるノード（根を含む） |
| 本線 | 各ノードの最初の子をたどった手順（`children[0]`） |
| 変化 | 本線以外の子から始まる手順 |
| 今のノード（カーソル） | 盤に表示している局面のノード |
| 今の手順 | 根 → 今のノード → その先（最後に選んだ子、なければ最初の子をたどる）の一本道。着手のログに出す範囲 |

## 3. データモデル

### 3.1 SGF のコア

```ts
/** プロパティの値は、SGF のファイルに書かれている形（[ と ] の間）のまま持つ。エスケープも解かない */
type PropValues = readonly string[];

interface SgfNode {
  /** 実行時だけの識別子。保存しない。編集でノードを作り直しても同じノードなら同じ id を引き継ぐ */
  readonly id: number;
  /** プロパティ。読み込んだ順を保つ */
  readonly props: ReadonlyMap<string, PropValues>;
  /** children[0] が本線 */
  readonly children: readonly SgfNode[];
}
```

- プロパティは汎用の入れ物（名前 → 値の列）として持ち、型付きの読み書きは関数で行う（`moveOf(node)`、`setupOf(node)`、`trianglesOf(node)` など）。こうすると「ツリー = SGF」がそのまま成り立ち、知らないプロパティも自然に往復できる。
- 値のエスケープを解かずに持つのは、解き方が型で変わるため（Text は改行を残し SimpleText はスペースにする。composed の区切りの `:` は、エスケープを解くと値の中の `:` と区別できなくなる）。型を知らないプロパティのソフト改行なども往復で変わらない。解く・作るのは `sgf/values.ts` で行い、書き出すときは値が構文を壊さないか（エスケープされていない `]` や末尾の `\`）を確かめる。
- ツリーは**不変（immutable）**にする。編集は、変えたノードから根までを作り直して新しい根を返す（パスコピー）。変えていない部分木は前の版と共有する。
  - 元に戻す／やり直すは「根とカーソルの組」を積むだけになる（§8）。
  - 作り直したノードは元の `id` を引き継ぐので、カーソル（今のノードの `id`）は編集をまたいでも有効。
- 1 つの盤面 = 1 つのゲームツリー。SGF のコレクション（複数のツリー）は読み込み時に盤面ごとに分ける。

根に置く標準のプロパティ: `GM[1]`、`FF[4]`、`CA[UTF-8]`、`AP`、`SZ`、`GN`（盤面の名前）。

### 3.2 拡張プロパティ

接頭辞 `GB`（goban）を付けた大文字のプロパティにする（名前は §12 で確認）。

| プロパティ | 置く場所 | 意味 | なぜ標準では足りないか |
| --- | --- | --- | --- |
| `GBMV[]` | `AB` か `AW` を 1 点だけ持つ配置ノード | この石は「取りなしの着手」。局面としては配置（取りが起きない）だが、着手のログと番号では 1 手として扱う | 「何もしない」モードの、取りや自殺が起きるはずの手。`B`/`W` で書くとほかのソフトでは取りが起きて局面が変わる。局面の正しさを標準側で守り、「手として数える」ことだけを拡張にする |
| `GBNS[]` | どのノードでも | このノードより後の手から番号を付ける（相対番号ではこの次の手が 1） | 番号を付け始める位置を表すプロパティが SGF にない（`MN` は手数を変えるもので、番号を付けない手を表せない） |

拡張はこの 2 つだけで済むように設計している（「△マーク」は経路から導出するので拡張は要らない。§12 の 1）。

### 3.3 SGF の外に持つ状態

| 状態 | 置き場所 | 理由 |
| --- | --- | --- |
| 置くもの（「配置」モードを含む）・囲まれた石の扱い・座標・見た目・番号の表示／付け方・書く文字・ツリーとコメントの欄の開け閉め | 全体の設定（今と同じ） | 入力や表示の設定で、記録ではない |
| 今のノード | 盤面ごとのメタデータ（根からの子の番号の列で保存） | 画面の状態 |
| 表示範囲（拡大） | 盤面ごとのメタデータ。書き出しでは `VW`、読み込みで `VW` があれば反映 | 編集中に頻繁に変わる画面の状態。図として残したい範囲は書き出しで `VW` にする |
| 手番の手動の入れ替え | 今のノードが配置ノードなら `PL` に書く。着手ノードなら盤面ごとのメタデータに一時的に持つ（ノードを移ったら消える） | 着手ノードには `PL`（配置のプロパティ）を混ぜられない（§13） |
| 盤面の名前 | 根の `GN` | 記録の一部として SGF に入れ、二重に持たない |
| 一覧のサムネイル用の盤面 | 盤面ごとのメタデータにキャッシュ | 一覧を出すたびに全盤面の SGF を読まないため。正は SGF 側 |

## 4. 局面の導出

### 4.1 打ち直し

今のノードの局面は、根から今のノードまでの各ノードを順に実行して求める。

1. `AE` → `AB` → `AW` を上書きで反映する（取りは起きない）。
2. `B` / `W` があれば、標準のルールで打つ（相手の呼吸点のない連を取る）。
3. 読み込んだファイルの不正な手は寛容に実行する（石のある点への手は上書き、自殺手は自分の連を取り除く）。このアプリ自身の編集では不正な手は作らない。

あわせて次のものを導出する:

- 経路上の着手の一覧（ノードへの参照つき）。着手のログ・着手番号・盤面一覧の手数に使う。盤上に残っていない手の判定は今の `movesOnBoard` と同じ。
- 番号の起点: 経路上でいちばん深い `GBNS` を持つノード。なければ根。
- 次の手番: 一時的な入れ替え（§3.3）があればそれ。なければ、経路をさかのぼって今のノードにいちばん近い「着手か `PL`」で決める（着手ならその反対の色、`PL` ならその色）。どちらもなければ黒。
- 取られた石の一覧（「△マーク」の表示用、§5 の表）。

### 4.2 キャッシュ

- 19 路で 300 手を根から打ち直すと約 3.4ms（この開発環境の Node で測定）。毎回打ち直しても使えるが、ドラッグ中の描画を軽くするためキャッシュする。
- 今の経路の各ノードの局面を配列に持つ。子を足したときは親の局面に 1 手打つだけ、経路の途中を編集したときはその深さから先を作り直す。

## 5. 既存機能の対応

| 既存の機能 | 新しい表現 | 挙動の変化 |
| --- | --- | --- |
| 石を置く（取り除く） | 今のノードに子の着手ノード `B`/`W` を足してそこへ移る。同じ手の子がすでにあれば、足さずにその子へ移る | 今のノードに子があると変化になる（新機能） |
| 黒・白の連打、ドラッグで置く | 同じ色の着手ノードを続けて足す（同じ色が続く着手は SGF で許される。§13） | なし |
| 何もしない | 標準のルールで取りも自殺も起きないなら普通の着手ノード。起きるなら `AB`/`AW` + `GBMV` | なし |
| △マーク | 着手は普通の `B`/`W`。△の石は記録に持たず、経路上の手で取られ、その点にまだ石が置かれていない石を△で表示する。△の点にはそのまま打てる | **あり**: △の石を消してから打つ必要がなくなる（§12 の 1） |
| 最後に置いた石を消す | 今のノードを消して親へ移る（今のノードに子があるときは §12 の 4）。今のノードが配置ノードでも、経路上の最後の着手ノードから今のノードまでが子 1 つずつの配置ノードの一本道なら、その着手ノードを抜く（`GBNS` は親に移す） | なし（子がないとき） |
| ほかの石を消す | 子の配置ノード `AE` を足して移る。交互モードなら消した石の色を `PL` に書く。今のノードが子のない配置ノードなら、そのノードの `AB`/`AW`/`AE` を直す | なし（ログの取り消し線も今と同じ判定） |
| 手で付ける△ | 今のノードの `TR` | 下の「印の引き継ぎ」を参照 |
| 文字 | 今のノードの `LB` | 同上 |
| 印の引き継ぎ | 子のノードを作るとき、親の `LB` と、盤上に残る石の `TR` を子にコピーする | SGF の印はノードごとなので、コピーしないと次の手で消える。コピーすれば今の挙動と同じに見える（§12 の 2） |
| 着手のログ | 今の手順の着手ノード | 今の手順の先（今のノードより後）も出し、今のノードを強調する |
| ログの手をタップして番号の起点にする | ログのタップはその手への移動（§12 の 3）。番号の起点は「ここから番号」で今のノードに `GBNS` を付ける（今の手順の上に 1 つだけ。元に戻せる） | **あり**（段階 3） |
| 番号の「1から」／「手数」 | 表示の設定（今と同じ）。「手数」は `MN` があればそれに従う | なし |
| 交互の手番 | §3.3、§4.1 | なし |
| 拡大 | 盤面ごとのメタデータ（§3.3） | なし |
| 盤面の名前 | `GN` | なし |
| 盤サイズの変更、盤面のクリア | 新しいツリーにする（根の `GN` は残す）。元に戻せる | なし |
| 元に戻す／やり直す | ツリーの版の履歴（§8） | なし |
| PNG 保存 | 今のノードの局面を描く | なし |
| SGF 保存 | ツリーをそのまま書き出す。前回入れた「打ち直せたら手順、だめなら配置」の変換は不要になる | 変化と拡張も入る |
| 盤面の一覧 | 手数とサムネイルは今のノードの局面から | なし |

## 6. 編集の規則

UI の操作（タップ・ドラッグ）をツリーの編集に変える処理は、DOM に依存しない関数にまとめてテストする（`src/edit.ts`）。

- 着手ノードには配置のプロパティ（`AB`/`AW`/`AE`/`PL`）を足さない。必要なら子の配置ノードを作る（§13）。
- 配置ノードをその場で書き換えるのは、子がないときだけにする。子があるノードを書き換えると、その先の全局面が変わるため。ただし「配置」モードは、その先の局面ごと直すための操作なので、子があっても今のノードを直す（§7.6）。
- 1 つのノードの中で同じ点を `AB`/`AW`/`AE` に重複させない。`TR` と `LB` も 1 点に 1 つ。
- ドラッグ 1 回分の編集は、元に戻す 1 回分にまとめる（今と同じ）。

## 7. 変化図（新機能）

### 7.1 作る・選ぶ

- 子のあるノードで、子と違う手を打つと新しい変化になる（最後の子として足す）。
- 移動: 「前の手」「次の手」「最初」「最後」、分かれ目での「別の変化へ」。キーボードは ← → で前後、↑ ↓ で変化の切り替え。
- 盤上に次の手の候補を表示する（子の手の位置に小さな印や A・B…）。表示するかは設定にする。
- 着手のログは今の手順を表示し、分かれ目に変化の数を出す。分かれ目をタップすると変化の一覧から選べる。

### 7.2 整理する

- 変化を本線にする（子の並べ替え）。
- 変化を削除する／この手から先を削除する（確認あり。元に戻せる）。

### 7.3 変化図の図面

- `GBNS` で変化の分かれ目から番号を付け直せるので、本の変化図のように「変化 1 から番号を振った図」を PNG で保存できる。番号の起点は経路上でいちばん深い `GBNS` なので、本線と変化でそれぞれ起点を持てる。

### 7.4 段階 3 で決めた細部

- 今の手順は画面の状態として持ち（`nav.ts` の `line`）、保存しない。編集の後は、前の手順の最後のノード（id）がまだあって今のノードを通るなら保ち、なければ今のノードから最初の子をたどる。
- **今の分かれ目**: 今のノードに子が 2 つ以上あれば次の手の分かれ目、なければ経路をさかのぼっていちばん近い分かれ目。「変化」のボタン・↑ ↓・変化の一覧はこれを対象にする。
- 変化を切り替える・一覧から選ぶと、今のノードは分かれ目の手前（変化の親）にし、選んだ変化を盤上の候補（枠付き）とログに出す。▶ でその変化に進む。続けて ↑ ↓ を押しても同じ分かれ目のまま切り替わる。
- 次の手の候補は、子の最初のノードが手のものだけを A・B… で盤に出す（配置ノードやパスは出せない）。設定は「表示しない」「変化だけ」（子が 2 つ以上、既定）「いつも」。候補の点をタップすると、置く色が違ってもその子へ進む。PNG には出さない。
- 「本線にする」は、選んでいる変化までの経路の各分かれ目で、たどる子を最初の子に並べ替える。
- 「この変化を削除」「今の手から先を削除」は確認してから消し、取り消しで戻せる。今のノードが消える部分にあれば、消したノードの親に移る。
- 元に戻すの履歴には、ツリー（根）が変わった操作だけを積む。子の手へ進む・親へ戻るだけのタップや、着手ノードでの手番の一時的な入れ替えは積まない。

### 7.5 ツリーの表示

- ツリー全体を小さなグラフで見せる（`tree-layout.ts` で配置を求め、`tree-view.ts` で描く）。ノードをタップするとその局面へ移る。今の手順がそのノードを通るなら手順は保ち、通らなければそのノードから最初の子をたどる。
- 配置: 列は深さ。行は、前順（最初の子から先）にたどりながら、その列の空いている行のうち親の行より下の最初のものにする。最初の子はふつう親と同じ行に並ぶ。親から子への線は、親の列を子の 1 行上まで下り、子へ斜めに入る。前順で置くので、この線はほかのノードや線と重ならない。
- 手は石の色の丸に手数（MN に従う。1000 以上は省く）、配置ノード（根を含む）は四角、コメントのあるノードには点を付ける。今の手順のノードと線は濃く、ほかは薄く描き、今のノードに輪を付ける。
- 10 万ノードの棋譜でも扱えるよう、配置は再帰を使わず型付き配列に持ち、根が変わったときだけ求め直す。描くのは見えている範囲だけにする（canvas は入れ物の大きさにして、スクロールに合わせて動かす）。

### 7.6 段階 4 で決めた細部

- **「配置」モード**: 「置くもの」の「配置」で入れる。黒・白・交互の色で、空点をタップすると石を置き、石をタップすると消す（ドラッグで続けて置く・消す。交互でも手番は変わらない）。
  - 今のノードが配置ノード（根を含む）なら、子があってもそのノードの `AB`/`AW`/`AE` を直す。その先の局面もすべて変わる（詰碁の問題図を根に作り、正解・失敗を変化にする、など）。
  - 今のノードが着手ノードなら、子の配置ノードを足してそこへ移る（§6。子があれば変化になる）。続けて置くとそのノードを直す。
  - 直すときは、親の局面と同じになる点をノードから外す（`AE` も含めて余計な点を残さない）。消した石の `TR` は外す。
- **コメント**: 今のノードの `C`（Text）を欄で編集する。空白だけなら `C` を消す。打ち始めてから欄を離れるか、ほかの操作（盤のタップ・手順の移動・取り消しなど）をするまでを、元に戻す 1 回分にまとめる。着手のログ・ツリー・コメントのボタンで、コメントのあるノードに印を付ける。
- ツリーの表示・コメントの欄を開いているか、「配置」モードかは、全体の設定として保存する（§3.3）。

## 8. 元に戻す／やり直すと、手順の移動

- 元に戻す／やり直すは**編集**の履歴にする。1 件は `{ 根, カーソル }`。ツリーが不変なので、500 件持っても共有部分が多くて軽い。
- 手順の移動（前の手・次の手・変化の切り替え）は編集ではないので履歴に積まない。元に戻すと、その編集をした時点のカーソルに戻る。
- 今の「戻す」「進む」ボタンは、手順の移動と紛らわしくなる。名前と配置を見直す（§12 の 5）。

## 9. 保存形式と移行

### 9.1 新しい保存形式

```ts
// localStorage の goban.boards.v2
interface LibraryV2 {
  currentId: string;
  entries: Array<{
    id: string;
    createdAt: number;
    updatedAt: number;
    sgf: string;        // このツリー 1 つの SGF（拡張プロパティ込み）
    cursor: number[];   // 根から今のノードまでの子の番号
    view: View;
    turn?: 'B' | 'W';   // 着手ノードでの手番の一時的な入れ替え
    thumb?: string;     // サムネイル用の盤面（Board.serialize()）。キャッシュ
  }>;
}
```

- `moves`（今のノードまでの手数）も `thumb` と同じく一覧のためのキャッシュとして持つ。盤面の名前は SGF の `GN` だけに持つ（一覧を出すために読み込み時に全盤面の SGF を読む。数十個なら十分に速い）。
- 全体の設定は `goban.settings.v2` に移す。なければ `goban.state.v1` から盤面の項目を除いて引き継ぐ。
- 元に戻すの履歴は `{ 根, カーソル, 手番の一時的な入れ替え }`。盤面の名前（`GN`）の変更は履歴に積まず、元に戻しても今の名前を保つ。

### 9.2 今の保存データからの移行

初めて新しい版を開いたとき、`goban.boards.v1` の各盤面を変換して `v2` に書く。`v1` は消さずに残す（前の版に戻しても盤面が残るように）。

1. 根に `SZ` と `GN`（名前）を置く。
2. 着手の記録を順に打ち直して着手ノードにする。石のある点に打つ手があれば（手で消した石の跡に打った場合など）、その前に `AE` の配置ノードを挟む。
3. 打ち直した局面が保存されていた石の配置と違えば、最後に差分の配置ノード（`AB`/`AW`/`AE`）を足す。
   - 途中の局面はほかのソフトでは元と違って見えることがある（「何もしない」で置いた手の順は記録にないため）。最後の局面は必ず一致する。
4. 番号の起点 `numberFrom = k` は、k 手目の直前のノード（k = 0 なら根）に `GBNS`。
5. △と文字は最後のノードの `TR` と `LB` にする。
6. 手番は、最後のノードが配置ノードなら `PL`、着手ノードなら `turn`。
7. カーソルは最後のノード。表示範囲はそのまま。
8. 「△マーク」モードの取られた石の記録は移さない（新しい表現では経路から導出するため。表示が今と違うことがある）。

## 10. 読み込み・書き出し

- 読み込み（新機能）: 「開く」でファイルを選ぶ。コレクションの各ツリーを新しい盤面として一覧に加える。
  - `SZ` が 2〜25 の正方形の盤だけ受け付ける（`Board` の上限）。長方形の盤や囲碁以外（`GM` が 1 以外）は理由を出して断る。
  - 文字コードは `CA` に従って `TextDecoder` で読む。仕様では `CA` がないときの既定は ISO-8859-1 だが、実際には UTF-8 や（日本の古いソフトの）Shift_JIS で `CA` のないファイルが多い。そこで `CA` がなければ UTF-8 → Shift_JIS → ISO-8859-1 の順に、正しく読めるものを使う（`decodeSgf`）。
  - 外部入力として扱う: ファイルの大きさとノード数に上限を設け、構文の誤りは位置つきで知らせる。FF[3] の書き方（プロパティ名の小文字、パスの `tt`）も読めるようにする。
- 書き出し: ツリーをそのまま SGF にする。拡張プロパティもそのまま書く（ほかのソフトでは無視される）。

## 11. モジュール構成と段階

```

src/sgf/write.ts     ツリー → SGF の文字列
src/sgf/values.ts    点・点のリスト（圧縮形式を含む）・テキスト・composed の読み書き
src/tree.ts          不変ツリーの操作（子を足す・ノードを直す・削除・並べ替え・id とカーソル）
src/game.ts          局面の導出（打ち直し・着手の一覧・番号の起点・手番・取られた石・キャッシュ）
src/ext.ts           拡張プロパティ（GBMV / GBNS）の読み書き
src/edit.ts          UI の操作 → ツリーの編集（DOM に依存しない）
src/nav.ts           手順の移動と変化（今の手順・分かれ目・切り替え・本線にする・削除。DOM に依存しない）
src/tree-layout.ts   ツリー全体の表示の配置（DOM に依存しない）
src/tree-view.ts     ツリー全体の表示の描画（canvas）

src/persistence.ts   全体の設定の保存（goban.settings.v2）
src/app.ts           UI（ポインタ・パネル）。状態はツリー + カーソル + 設定だけ
```

`capture.ts`（取られた石の記録）と `sgf.ts`（以前の SGF 出力）は段階 2 で削除し、`moves.ts` は経路の着手の一覧を受け取る形に直した。`board.ts`・`renderer.ts`・`layout.ts`・`view.ts`・`coords.ts` はほぼそのまま使う。

段階ごとに別のプルリクエストにする:

1. **SGF のコア**: `sgf/*`・`tree.ts`・`game.ts`・`ext.ts` とテスト（読み書きの往復、圧縮した点のリスト、エスケープ、打ち直し）。画面は変えない。
2. **アプリをツリーの上に載せ替える**: `edit.ts`、保存形式 v2 と移行、元に戻すの作り直し、SGF の読み込み。見た目と操作は今と同じ（§5 で「あり」とした点と、子がある所に打つと変化ができることだけが変わる）。いちばん大きい段階。
3. **変化図の UI**: 手順の移動、次の手の候補の表示、変化の一覧・本線にする・削除、変化から番号を振った図。
4. **その先**: ツリー全体の表示、「配置」モード（今のノードの `AB`/`AW` を直接直す。詰碁の問題図を根に作り、正解・失敗を変化にする、など）、コメント（`C`）。

## 12. 決定事項

1. **「△マーク」モード**: △の石は記録に持たず、手順（経路）から導出する。△の点にはそのまま打てる（先に△を消さなくてよい）。拡張プロパティは足さない。
2. **印の引き継ぎ**: 子のノードを作るとき、親の△（盤上に残る石のもの）と文字をコピーする。これを既定にし、設定で切れるようにする。
3. **着手のログの手をタップしたとき**: その手へ移動する。番号の起点は別のボタン（「今のノードから番号」）で付ける。
4. **子のある手の石をタップしたとき**: その手を消さずに親へ移るだけにする（その先の手順は変化として残る）。消すのは「この手から先を削除」で行う。
5. **ボタンの名前**: 編集は「取り消し」「やり直し」、手順の移動は ◀ ▶ のような表記に分ける。
6. **拡張プロパティの名前**: 接頭辞 `GB`（`GBMV`、`GBNS`）。
7. **盤面の名前**: 根の `GN` に入れる。読み込んだ棋譜に `GN` がなければ「黒 対 白」（`PB`・`PW`）などから名前を作る。

## 13. SGF の仕様の確認

仕様書（red-bean.com の sgf4.html・properties.html・go.html・ff3.html・ff5/m_vs_ax.htm）で確かめた結果。設計はこれに合っている。

| 確かめたこと | 仕様 | 設計への反映 |
| --- | --- | --- |
| 着手と配置のプロパティを同じノードに混ぜてよいか | 混ぜてはいけない。着手（move）は `B`/`W`/`KO`/`MN` など、配置（setup）は `AB`/`AW`/`AE`/`PL`。`B` と `W` も混ぜてはいけない。1 つのノードに同じプロパティは 1 つだけ | §6 のとおり。読み込みでは寛容に、同じプロパティが 2 回あれば値をつなげ、着手と `PL` が混ざっていれば着手を優先する |
| `AB`/`AW`/`AE` の意味 | 上書きで、取りも自殺も起こさない（呼吸点のない石もそのまま残す）。1 つのノードの中で点を重複させてはいけない | §4.1 のとおり。重複していれば `AE` → `AB` → `AW` の順に上書きする |
| 同じ色の着手が続いてよいか、不正な手 | 同じ色の連続について明記はないが、`B`/`W` は「構文が正しければ、手が不正でも実行する」とあり、禁止されていない。石のある点への手も、打つ前の状態に関わらず石を置き、相手の連の取り → 自分の連の自殺の順に判定する | §4.1 のとおり。石のある点への手は上書き、自殺手は自分の連を取り除く |
| パス | `B[]`。19 路以下では FF[3] との互換で `B[tt]` も | 両方をパスとして読む。パスも 1 手に数える |
| 印 | ノードごとで、子に引き継がれない（引き継ぐのは `DD`・`VW`・`PM` だけ）。`CR`/`MA`/`SL`/`SQ`/`TR` は 1 点に 1 つ。`LB` は点の重複不可（ほかの印との重なりは禁止されていない） | §5 の「印の引き継ぎ」のとおり、子を作るときにコピーする |
| 独自プロパティの名前 | FF[4] は大文字だけ（構文は `UcLetter { UcLetter }` で長さの制限はない。標準のものは今のところ 2 文字まで）。標準のプロパティの名前を使ってはいけない。FF[3] は小文字を無視する（`LaBel` は `LB`） | `GBMV`・`GBNS` は構文に合う。読み込みでは小文字を取り除く |
| 知らないプロパティ | 残すべき（残せないなら警告する） | §1 の方針 4 のとおり |
| `MN` | このノードの手の手数をその値にする | 着手の手数（`GameMove.number`）に反映する |
| `VW` | 見える点のリスト（elist of point）。引き継がれ、`VW[]` で解除 | §3.3 のとおり、書き出しでは根に 1 つだけ書く |
| 圧縮した点のリスト | list of point / elist of point の型と、Go の `AB`/`AW`（list of stone）で使える。`AE`・`TR`・`CR`・`MA`・`SL`・`SQ`・`VW`・`TB`・`TW`・`DD` など。`LB`・`AR`・`LN` は composed なので対象外 | `parsePointList` で展開する。書き出しは圧縮しない |
| テキスト | エスケープは `\`（後ろの文字をそのまま入れる）。`]`・`\` と、composed の中の `:` をエスケープする。`\` の直後の改行（ソフト改行）は取り除く。改行以外の空白はスペースにする。SimpleText では改行もスペースにする | `decodeText`・`decodeSimpleText`・`encodeText`（`:` は常にエスケープする） |
| `CA` | 根のプロパティ。Text・SimpleText の文字コード。既定は ISO-8859-1 | §10 |
| 空白 | 値・プロパティ・ノード・手順・ゲームツリーの間ならどこにあってもよい | 読み込みで許す |

「△マーク」モードの自殺手は、以前の版と同じく置かない（取られた石を空点とみなして「取り除く」モードと同じに判定していたため）。そのため「このアプリ自身の編集では不正な手は作らない」と食い違わない。
